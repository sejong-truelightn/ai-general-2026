머신러닝은 데이터 드리븐이다

데이터 드리븐(data-driven)이란?

규칙을 사람이 직접 짜 넣지 않고, 데이터에서 규칙을 찾게 하는 방식입니다.

RULE-BASED

전통적인 프로그래밍

입력 + 사람이 만든 규칙 → 출력

개발자가 규칙을 if문으로 하나씩 씁니다.
예) 제목에 ‘무료’가 있으면 스팸

DATA-DRIVEN

머신러닝

입력 + 정답 → 학습 → 규칙(모델)

사람은 규칙 대신 예시 데이터와 정답을 줍니다.
예) ‘스팸’·‘정상’이 표시된 메일 수만 통을 주면, 어떤 특징이 스팸과 관련 있는지 모델이 배웁니다.

데이터가 중요

알고리즘이 같아도 데이터의 양과 질에 따라 결과가 크게 달라집니다.

말로 못 쓰는 규칙

고양이를 알아보는 규칙은 코드로 쓰기 어렵지만, 사진으로 배울 수 있습니다.

다시 학습

스팸 수법이 바뀌면 규칙을 새로 짜는 대신 새 데이터로 다시 학습시킵니다.

편향도 배운다

데이터가 한쪽으로 치우쳐 있으면 모델도 치우친 판단을 합니다.

핵심 정리

지도 학습 프레임워크 — 네 단계

지도 학습은 정답이 붙은 데이터로 배웁니다. 사람은 형태와 목표만 정하고, 값(파라미터)은 데이터로 정합니다. 딥러닝도 같은 틀입니다.

STEP 1

모델의 형태를 정한다

입력과 출력의 관계를 어떤 수식 모양으로 볼지 정합니다. 예) f(x) = ax

STEP 2

목표를 정의한다

모델이 잘했는지 판단할 채점 기준을 수식으로 씁니다. 예) y ≈ f(x)가 되도록

STEP 3

학습(최적화)

훈련 데이터 {(xᵢ, yᵢ)}로 목표를 가장 잘 달성하는 a를 찾습니다.

STEP 4

예측(추론)

처음 보는 x에 대해 ŷ = ax를 계산해 라벨을 추정합니다.

핵심 정리

표기법 약속

앞으로 모든 슬라이드에서 같은 기호와 같은 색을 씁니다.

기호와 뜻 (머신러닝의 관례)

기호뜻
x데이터 · 입력 · 특징(feature). 관측해서 얻은 값
y정답 · 라벨(label). 모델이 맞혀야 하는 값
a, β파라미터(parameter). 모델 속에서 배워야 하는 값
ŷ모델의 예측값 (“와이 햇”)
n훈련 데이터 개수

슬라이드에서는 항상 같은 색으로 씁니다. 파랑=데이터, 초록=정답, 빨강=파라미터.

용어

  • y (매출) = Response, Target, 종속변수
  • x (광고비) = Feature, Input, Predictor, 독립변수
  • 둘을 잇는 함수 f = 회귀 함수(regression function)
y = f(x) + ε ε(입실론) = 오차. 실제 데이터는 수식과 정확히 맞지 않습니다.

같은 광고비를 써도 매출은 매번 다릅니다 → 정답 y는 하나의 값이 아니라 분포를 갖습니다. 그래서 모델은 보통 그 분포의 평균(기대값)을 맞히도록 설계합니다.

입력 세 개를 묶어 입력 벡터 하나로 부릅니다.

x =x₁x₂x₃∈ ℝ³

y = f(x) + ε

ε은 측정 오차와 그 밖의 어긋남을 모두 담는 항이고, x와 독립이라고 가정합니다. x가 어떤 값이든 ε이 흔들리는 정도는 같다는 뜻입니다. 실제로는 정확히 같지 않은 경우가 많지만, 계산을 단순하게 하려고 이렇게 가정합니다. 또 ε의 평균은 0이라고 가정합니다. 규칙적인 부분은 모두 f(x)에 넣고, ε에는 흔들림만 남기기 때문입니다.

STEP 1

모델의 형태를 정한다

머신러닝 전체에서 사람의 판단이 가장 많이 들어가는 단계입니다.

PARAMETRIC

파라메트릭 모델

함수의 모양을 먼저 가정하고, 그 안의 계수만 데이터에서 찾습니다.

y = β₀ + β₁x₁ + β₂x₂ + β₃x₃

찾을 숫자는 데이터 양과 상관없이 4개입니다.
선형회귀와 대부분의 딥러닝 모델이 해당합니다.

NON-PARAMETRIC

넌파라메트릭 모델

함수 모양을 가정하지 않습니다. 비슷한 데이터의 값으로 답을 정합니다.

ŷ = 가까운 K개 이웃의 평균

데이터 모양에 아주 유연하게 맞지만, 데이터가 많이 필요하고 데이터 자체를 다 들고 다녀야 합니다. (예: K-NN 회귀)

그래도 직선 모델부터 쓰는 이유

① 해석이 쉽습니다 ② 데이터가 적어도 안정적입니다 ③ 좁은 범위에서는 대부분 직선에 가깝습니다

STEP 1 · 모델링의 목표

진짜 f를 평면 하나로 근사하기

학력(education)과 연차(seniority)로 소득(income)을 예측하는 문제입니다.

파란 면

세상의 진짜 관계 f. 존재하지만 우리는 직접 볼 수 없습니다. 데이터를 통해 짐작할 수만 있습니다.

빨간 점

우리가 가진 데이터. 진짜 f 위에 오차 ε가 얹혀 흩어져 있습니다. 우리가 볼 수 있는 것은 이 점들뿐입니다.

노란 면

점들로부터 학습한 선형회귀 모델 f̂ — 평평한 평면입니다.

f̂(education, seniority) = β₀ + β₁×education + β₂×seniority “평면”이라 가정했으니, 팀장 승진에서 연봉이 확 뛰는 구간은 데이터를 100만 개 모아도 표현할 수 없습니다. 이런 한계를 편향(bias)이라고 합니다.
STEP 1 보충

편향(bias)과 분산(variance)

데이터를 20번 새로 뽑아 각각 학습했습니다. 옅은 선은 각 결과, 진한 선은 그 평균, 점선은 진짜 f입니다.

편향 (bias)

모델의 평균이 진짜 f에서 벗어난 정도입니다. 가정한 모양이 틀려서 생기므로 데이터를 더 모아도 줄지 않습니다.

예) 왼쪽 직선은 진한 선이 점선과 계속 어긋납니다. 소득 예제에서 평면이 팀장 승진 구간을 잡지 못하는 것도 편향입니다.

분산 (variance)

훈련 데이터가 다르게 뽑혔다면 모델이 얼마나 달라졌을지입니다. 모델이 유연할수록, 데이터가 적을수록 커집니다.

예) 오른쪽 9차 곡선은 점마다 붙은 잡음까지 따라 구부러져서 옅은 선들이 넓게 퍼집니다. 평균은 진짜 f에 가깝습니다.

둘을 함께 줄이기는 어렵습니다. 모델을 유연하게 만들면 편향은 줄고 분산은 커집니다. 이것을 편향-분산 트레이드오프라고 합니다.

STEP 1 예시

같은 데이터, 다른 가정 → 다른 모델

데이터는 똑같습니다. 사람이 STEP 1에서 무엇을 가정했는지만 다릅니다.

직선 가정

파라미터 2개. 굽은 관계는 놓치지만, 경향은 안정적으로 잡고 해석이 쉽습니다.

4차 곡선 가정

파라미터 5개. 굽은 관계도 잡습니다. 다만 차수를 더 올리면 잡음까지 따라갑니다.

가정 없음 (K-NN 회귀, K=1)

수식이 없습니다. 가장 가까운 점의 값을 그대로 써서 계단 모양이 됩니다. CEO 연봉 같은 엣지 케이스도 비슷한 다른 CEO의 연봉으로 답합니다.

정답은 없습니다. 데이터의 양, 문제의 성격, 해석 필요 여부에 따라 사람이 고릅니다.

STEP 2

목표를 수식으로 — 평균 제곱 오차(MSE)

예측이 y에 얼마나 가까운지 계산하려면 숫자로 채점하는 기준이 필요합니다.

MSE = (1/n) Σᵢ ( yᵢ − f̂(xᵢ) )² (정답 − 예측)의 제곱을 평균낸 값입니다. 작을수록 좋고, 크게 틀린 점에 더 큰 값이 매겨집니다.

직접 채점해 보세요

빨간 막대가 오차(residual)입니다. MSE는 이 막대들을 제곱해서 평균낸 값.

STEP 2 보충

줄일 수 있는 오차와 줄일 수 없는 오차

E[(y − ŷ)²]  =  ( f(x) − ŷ )²  +  Var(ε) Reducible 줄일 수 있는 오차  ·  Irreducible 줄일 수 없는 오차
y − ŷ = ( f(x) − ŷ ) + ε
← y = f(x) + ε 대입
(y − ŷ)² = ( f(x) − ŷ )² + 2( f(x) − ŷ )ε + ε²
← 제곱 전개
E[(y − ŷ)²] = ( f(x) − ŷ )² + 2( f(x) − ŷ )·E[ε] + E[ε²]
← 양쪽에 평균(E)
E[(y − ŷ)²] = ( f(x) − ŷ )² + 0 + Var(ε)
← E[ε] = 0, E[ε²] = Var(ε)

줄일 수 있는 오차

모델이 부족해서 생기는 오차. 더 좋은 모델 · 더 많은 데이터 · 더 나은 학습으로 줄일 수 있습니다.

머신러닝 연구는 대부분 이 항을 줄이는 방법을 다룹니다.

줄일 수 없는 오차

세상 자체의 무작위성, 그리고 우리가 측정하지 못한 요인에서 옵니다.

같은 광고비라도 날씨, 경쟁사 세일 등에 따라 매출이 다릅니다. 어떤 모델로도 맞힐 수 없습니다.

STEP 3

학습 = 최적화(Optimization)

STEP 2에서 정한 채점 기준을 가장 잘 만족하는 파라미터를 찾는 과정입니다. 이것을 훈련(training)이라 부릅니다.

① 식을 풀어서 구하기 (closed-form)

MSE를 가장 작게 만드는 a를 식을 풀어서 한 번에 구합니다. (이차함수의 꼭짓점을 구하는 것과 같습니다.)

정확하고 빠르지만, 간단한 모델에서만 가능합니다. (선형회귀 등)

② 조금씩 찾아가기 (경사하강법)

공식이 없는 복잡한 모델은, 아무 값에서 시작해 오차가 줄어드는 방향으로 조금씩 이동하며 찾습니다.

이 방법을 경사하강법(Gradient Descent)이라고 합니다. 딥러닝은 이 방식으로 학습합니다.

식을 풀어서 a 구하기

데이터는 (1, 3), (2, 5), (3, 4), (4, 8)이고, 모델은 f(x) = ax입니다. a를 바꿔 가며 MSE를 계산하면, MSE는 a에 대한 이차함수가 됩니다.

MSE(a) = ¼ [ (3 − a)² + (5 − 2a)² + (4 − 3a)² + (8 − 4a)² ]
← MSE를 a의 식으로
MSE(a) = ¼ ( 30a² − 114a + 114 )
← 전개해서 정리
a = 114 / (2 × 30) = 1.9
← 꼭짓점의 가로 위치 (a² 앞 30, a 앞 −114)

STEP 4

예측하고 성능 평가하기

학습이 끝나면 a를 알고 있으므로, 처음 보는 x에 대해 ŷ = ax를 계산하면 됩니다. 이것을 추론(inference)이라고 합니다.

잘못된 방법: 훈련 데이터로 채점하기

모델은 훈련 데이터를 이미 봤습니다. 그걸로 채점하면 시험 문제를 미리 보고 친 시험과 같습니다.

점수는 높게 나오지만 새 데이터에서는 성능이 크게 떨어질 수 있습니다.

올바른 방법: 테스트 데이터로 채점하기

데이터를 미리 훈련용 / 테스트용으로 나눕니다. 테스트 데이터는 학습 중에 절대 보여주지 않습니다.

알고 싶은 것은 외운 실력이 아니라 처음 보는 문제를 푸는 실력 = 일반화(generalization)입니다.

전체 데이터  →  훈련 80%  +  테스트 20% 비율은 상황마다 다르지만, 테스트 데이터를 학습에 쓰지 않는다는 원칙은 항상 지켜야 합니다.

훈련·테스트 오차 모두 낮음 (목표)

OVERFITTING

과적합

모든 점을 지나가려다 곡선이 구불구불해집니다.

훈련 오차 낮음, 테스트 오차 높음

그럼 적정한 차수는 어떻게 찾을까요?

차수처럼 학습 전에 사람이 정하는 값을 하이퍼파라미터라고 합니다. 기울기 a, 계수 β처럼 학습으로 정해지는 파라미터와 구분합니다. 하이퍼파라미터는 후보마다 학습해 보고 결과를 비교해서 고릅니다.

모델 복잡도 정하기

테스트 오차가 가장 낮은 차수를 고르면 되지 않나요?

앞의 U자 곡선만 보면 그렇게 하고 싶습니다. 하지만 그렇게 하면 테스트 데이터로 공정하게 평가할 수 없게 됩니다.

① 훈련 오차로 고르면

차수를 올릴수록 무조건 내려갑니다.

항상 가장 복잡한 모델(과적합 데모의 차수 12)이 뽑히므로 판단 기준이 될 수 없습니다.

② 테스트 오차로 고르면

시험 문제를 보고 공부법을 고르는 것과 같습니다.

고르는 데 쓴 순간 테스트 데이터는 더 이상 처음 보는 데이터가 아닙니다. 보고하는 점수가 실제보다 좋게 부풀려집니다.

③ 검증 데이터로 고르기

고르는 용도로만 쓰는 데이터를 하나 더 떼어 둡니다.

이것을 검증 데이터(validation)라고 합니다. 차수·K 같은 하이퍼파라미터는 여기서 정합니다.

고르는 데이터와 채점하는 데이터는 달라야 합니다

테스트 점수를 보고 모델을 고친 뒤 다시 테스트 점수를 보고하면, 그 점수는 내일 들어올 진짜 데이터에서의 성능을 더 이상 말해 주지 않습니다.

핵심 정리

문제집 · 모의고사 · 수능

STEP 4에서 둘로 나눴던 데이터를, 실제로는 세 덩어리로 나눠 씁니다.

훈련 데이터 · 70%
검증 · 15%

훈련 데이터 · 문제집

파라미터를 학습하는 데 씁니다 (STEP 3).

풀고 또 풀어도 됩니다. 답을 외워도 괜찮습니다.

검증 데이터 · 모의고사

하이퍼파라미터를 고르는 데 씁니다.

차수 1~12, K=1·5·15처럼 여러 후보를 여기서 겨루게 한 뒤 가장 잘한 것을 고릅니다. 여러 번 봐도 됩니다.

시험 데이터 · 수능

최종 성능을 보고할 때 딱 한 번 씁니다 (STEP 4).

모델을 고르는 데 절대 쓰면 안 됩니다. 최종 평가 전까지는 보지 않습니다.

시험 데이터를 보고 모델을 고르면 안 됩니다

실제 서비스에서는 이렇게 할 수 없습니다. 추천 시스템의 시험 데이터는 내일 들어올 사용자이고, 내일 일은 오늘 알 수 없습니다. 그런데 연구할 때는 데이터를 미리 떼어 두기 때문에 미리 보고 모델을 고르기 쉽습니다. 그렇게 얻은 96.8%는 실제 성능보다 높게 나온 값입니다.

왜 이렇게 하나

데이터를 한 번만 나누면 쉬운 부분이 검증에 들어가 점수가 좋게 나올 수도, 어려운 부분이 걸려 나쁘게 나올 수도 있습니다.

여러 번 돌려 평균을 내면 어떻게 나눴는지에 따른 차이가 줄어듭니다. 모든 데이터가 한 번씩 검증에 쓰여서, 특히 데이터가 적을 때 유용합니다.

자주 나오는 질문

“검증 데이터는 어디서 떼나요?”
시험 데이터를 뺀 나머지에서 떼어 냅니다. 시험 데이터는 여기에 섞이지 않습니다.

실제 진행 순서

학습부터 보고까지, 순서대로

4단계 틀에 모델 고르기 단계가 하나 추가됩니다.

  1. 데이터를 나눈다 — 시험 데이터를 먼저 떼어 따로 보관한다 이후 단계에서는 시험 데이터를 쓰지 않는다.
  2. 훈련 데이터로 학습한다 — STEP 1~3 차수 1짜리, 2짜리, …, 12짜리 후보 모델을 각각 학습시킨다. 파라미터는 여기서 정해진다.
  3. 검증 데이터(또는 교차검증)로 고른다 — 후보 중 가장 좋은 것을 선택 여기서 하이퍼파라미터(차수·K)가 정해진다. 2~3번을 여러 번 반복해도 된다.
  4. (선택) 다시 학습 — 고른 설정으로 훈련+검증 데이터를 합쳐서 한 번 더 학습 70%보다 85%로 학습하는 편이 조금 더 정확하다.
  5. 시험 데이터로 딱 한 번 성능을 측정해 보고한다 — STEP 4 이 값을 최종 성능으로 보고한다.
실제 진행 순서

검증 오차가 비슷하다면

3단계에서 후보를 비교할 때, 오차만으로 정하지 않고 아래 내용도 함께 봅니다.

함께 보는 것

  • 해석 가능성 — 예측 이유를 설명해야 하는 분야(의료·대출)
  • 단순함 — 성능이 같다면 간단한 모델을 고른다
    “모든 것은 가능한 한 단순해야 하지만, 그보다 더 단순해서는 안 된다.” (아인슈타인이 했다고 알려진 말)
  • 비용 — 학습·추론에 드는 시간과 돈

실제 진행 순서

시험 데이터는 마지막에 한 번만 씁니다

앞의 다섯 단계에서 지켜야 할 규칙과 데이터별 역할입니다.

절대 하면 안 되는 것

5번의 결과를 보고 3번으로 되돌아가는 것. 시험 점수를 보고 모델을 바꾸면, 시험 데이터는 더 이상 공정한 평가 기준이 아니게 됩니다.

다시 정리하면

파라미터(a, β) — 데이터가 정함 → 훈련 데이터
하이퍼파라미터(차수, K) — 사람이 후보를 정함 → 검증 데이터
최종 성능 — 시험 데이터, 단 한 번

또 하나의 큰 축 · 분류(CLASSIFICATION)

회귀는 주관식, 분류는 객관식

머신러닝 문제의 다른 한 축입니다. 4단계 틀은 그대로이고, 정답의 모양과 채점 기준이 달라집니다.

REGRESSION

회귀

답을 실수값으로 적습니다.

  • 광고비 → 매출 22.1
  • 학력 · 연차 → 연봉
  • 30cm 자의 실제 길이 → 29.99cm
CLASSIFICATION

분류

정해진 선택지 중에서 고릅니다. 선택지 개수는 유한합니다.

  • 이 메일은 스팸인가? → 예 / 아니오
  • 손으로 쓴 숫자 → 0 ~ 9 중 하나
  • 사진 한 장 → ImageNet의 1,000개 클래스 중 하나 (예: 고양이)
오류율 = 1⁄m Σᵢ₌₁m I( yᵢ ≠ ŷᵢ ) m = 테스트 데이터 개수. I( · )는 괄호 안이 참이면 1, 거짓이면 0입니다. 틀린 개수를 전체 개수로 나눈 값(틀린 비율)이므로 낮을수록 좋은 모델입니다. (정확도 = 1 − 오류율)
분류 · 넌파라메트릭 예시

왜 넌파라메트릭인가. 정해진 식도, 학습한 파라미터(a, β)도 없습니다. 훈련 데이터를 그대로 들고 있다가 물어볼 때마다 이웃을 찾습니다. 이웃의 값을 평균 내면 회귀에도 쓸 수 있습니다(K-NN 회귀). K는 사람이 정하는 하이퍼파라미터입니다.

오늘 정리

오늘 배운 것

  • STEP 1 모델의 형태 (사람) — 파라메트릭 / 넌파라메트릭
  • STEP 2 목표 정의 (사람) — MSE
  • 오차 = 줄일 수 있는 것 + 못 줄이는 것
  • STEP 3 최적화 (기계) — MSE를 가장 작게 만드는 파라미터를 구함
  • STEP 4 예측 + 테스트 데이터로 평가 = 일반화
  • 모델을 키울수록 좋은 게 아니다 → 과적합
  • 훈련 = 문제집 · 검증 = 모의고사 · 시험 = 수능, 그리고 교차검증
  • 회귀(실수값) vs 분류(선택지) — 오류율, K-NN
