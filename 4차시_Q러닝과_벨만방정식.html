Q(A)=0.63   Q(B)=0.54   Q(C)=0.41   Q(D)=0.22   Q(E)=0.17 Q값 = “이 행동을 고르면 앞으로 받을 점수의 기댓값”

Q(i) = 당첨 횟수 / 시도 횟수

당기면 그 자리에서 0 또는 1이 돌아왔으니까, 받은 점수를 세어 나누기만 하면 됐습니다.

고르는 법도 정해져 있었습니다

톰슨 샘플링은 “숫자 하나 대신 분포”로 이걸 더 영리하게 만든 것이었죠.

PART 2 · Q함수

“Q”라는 조언자가 있다고 상상해 봅시다

“지금 s3에 서 있는데, 아래로 가면 앞으로 몇 점쯤 받을까?”

— 이렇게 물어볼 수 있는 상대가 있다면?

Q( 상태 s, 행동 a )  =  예상 점수 입력 2개(어디에 있나 · 무엇을 하나) → 출력 1개(그러면 앞으로 받을 점수)

물어보면 이렇게 답해 줍니다

Q(s3, ↑)0.59
Q(s3, ↓)0.81 ← 제일 높다
Q(s3, ←)0.66
Q(s3, →)−0.90

그럼 아래로 가면 되겠네요. 고민 끝.

정식 이름

상태-행동 가치 함수
(state-action value function)

“상태와 행동을 함께 넣으면 그 가치를 돌려주는 함수”라는 뜻입니다. Q는 quality(질)의 첫 글자예요.

밴딧에서 쓴 Q(A), Q(B)… 는 상태가 하나뿐이라 생략됐던 같은 함수입니다.

표기법

max와 argmax — 헷갈리기 쉬운 두 글자

앞으로 계속 나옵니다. 지금 한 번에 정리하고 갑시다.

s3의 네 방향 Q값  =  ↑ 0.59 ↓ 0.81 ← 0.66 → −0.90

숫자를 묻는다
maxa Q(s3, a) = 0.81

“그중 가장 큰 값이 얼마냐”

답은 점수입니다. 0.81.

행동을 묻는다
argmaxa Q(s3, a) = ↓

“그 값을 만든 행동이 무엇이냐”

답은 방향입니다. 아래쪽.

한 문장으로

arg는 “argument(입력값)”의 줄임말입니다. max는 출력(값)을, argmax는 입력(행동)을 돌려줍니다.

Q러닝 알고리즘에는 이 둘이 각각 한 번씩 나옵니다 — 배울 때는 max, 움직일 때는 argmax.

POLICY

표만 있으면 길은 저절로 나온다

Q표가 완성되면, 지도는 따로 만들 필요가 없습니다.

상태↑↓←→고를 행동
s00.000.730.000.66↓
s30.590.810.66−0.90↓
s60.730.730.730.90→
s7−0.900.810.811.00→
π(s) = argmaxa Q(s, a) 정책(policy) — 각 칸에서 Q값이 가장 큰 방향을 고른다. 그게 전부입니다.

표의 각 줄에서 가장 큰 숫자에 동그라미를 치면, 그 화살표들이 곧 목표까지 가는 길이 됩니다.

s3에서 →가 −0.90인 걸 보세요. AI는 “오른쪽은 구덩이다”를 숫자로 기억하고 있습니다.

최적 정책 — π* optimal policy

만약 Q값이 전부 정확하다면, 매번 argmax를 따라가는 이 정책보다 더 나은 방법은 없습니다. 그때의 정책을 최적 정책 π* (optimal policy), 그때의 Q값을 최적 Q값 Q* (optimal Q)라고 씁니다.

별표(*)는 “이보다 나은 것은 없다”는 표시입니다.

그래서 오늘의 목표는 하나

전부 0으로 시작한 36칸짜리 표를, 경험만으로 Q*에 가깝게 채우는 것.

표만 채워지면 길은 argmax가 알아서 뽑아 줍니다.

PART 3 · 그럼 이 표를 어떻게 채우지

“끝까지 받을 점수의 합”을 어떻게 아나

표만 채워지면 길은 나옵니다. 문제는 그 숫자를 어디서 구하느냐입니다. 끝까지 가 보기 전에는 알 수 없어 보이는데요.

리턴(return) — 지금 시점부터 판이 끝날 때까지 받을 점수의 합. 기호로 G.

Gt  =  rt  +  rt+1  +  rt+2  +  rt+3  +  ⋯

둘째 항부터 괄호로 묶어 보면

Gt = rt + ( rt+1 + rt+2 + rt+3 + ⋯ )

↓ 괄호 안은 바로 Gt+1

Gt  =  rt  +  Gt+1 지금 받은 점수 + 나머지 전부

왜 이게 대단한가

끝까지 가 보지 않아도 됩니다. 한 걸음 앞만 알면 나머지는 “그다음 것”에 맡길 수 있으니까요.

긴 계산을 짧은 계산 + 나머지로 쪼갠 겁니다. 이런 구조를 재귀(recursion)라고 합니다.

첫 걸음부터 계산해 볼까요?

4걸음 만에 🏁에 닿는 길: 받은 점수는 0, 0, 0, 1

두 번째 G1 = 0 + G2 = ?
세 번째 G2 = 0 + G3 = ?

PART 3 · 연결

그런데 이 G, 어디서 본 것 같지 않나요?

5장에서

Q(s, a)의 정의

“s에서 a로 갔을 때,
판이 끝날 때까지 받을 점수의 합”

방금

리턴 Gt의 정의

“지금 시점부터
판이 끝날 때까지 받을 점수의 합”

같은 말입니다. 이름만 둘이었을 뿐이죠.

Q(s, a)  =  Gt  =  r  +  Gt+1 지금 받은 점수 r  +  도착한 칸부터 끝까지의 총점 Gt+1

무엇이 좋아졌나

Q값을 구하려고 판이 끝날 때까지 기다릴 필요가 없어졌습니다. 한 걸음만 가 보면 r을 알 수 있으니까요.

이제 딱 하나 남았습니다

Gt+1을 어떻게 알아내느냐.

도착한 칸부터 끝까지의 총점 — 이것도 결국 끝까지 가 봐야 아는 것 아닌가요?

PART 3 · 이름 붙이기

방금 우리가 한 일에는 이름이 있습니다

“큰 문제를 한 걸음 + 나머지로 쪼갠다” — 70년 전에 이미 나온 아이디어입니다.

1953년

리처드 벨만 (Richard Bellman)

미국 수학자. 여러 단계에 걸친 의사결정 문제를 푸는 방법을 정리했고, 이것을 동적 계획법(dynamic programming)이라고 불렀습니다.

그 핵심에 놓인 식들을 통틀어 벨만 방정식이라고 부릅니다. 강화학습만의 것이 아니라, 내비게이션의 최단 경로나 알고리즘 수업의 DP도 같은 뿌리입니다.

최적성의 원리

서울에서 부산까지 가는 가장 빠른 길이 대전을 지난다고 합시다.

서울 → 대전 → 부산 (가장 빠른 길)

그렇다면 대전 → 부산 구간도 반드시 대전에서 부산까지의 가장 빠른 길입니다.

아니라면, 그 구간만 바꿔서 전체를 더 빠르게 만들 수 있을 테니까요.

그래서 큰 문제를 쪼갤 수 있습니다

큰 문제  =  한 걸음  +  남은 작은 문제 남은 부분도 그 자체로 최적이라는 보장이 있으니, 안심하고 “거기서 최선을 다한다”고 가정할 수 있습니다

서울→부산의 소요 시간 = 서울→대전 시간 + 대전→부산의 최소 시간. 우리가 8장에서 Gt = rt + Gt+1 로 쪼갠 것이 정확히 이겁니다.

그럼 이제 우리 문제의 벨만 방정식을 써 봅시다 — “남은 작은 문제”의 값을 무엇으로 채울까요?

PART 3 · 답

우리 문제의 벨만 방정식

“남은 작은 문제”의 값 — 즉 Gt+1 자리에 무엇을 넣을까요?

남은 질문 하나 — Gt+1은 얼마인가?

Gt+1은 도착한 칸 s′부터 끝까지 받을 점수의 합입니다. 그럼 s′에서 최선을 다한다면 얼마를 받을까요?

그 값은 이미 표에 적혀 있습니다. s′칸의 네 Q값 중 가장 큰 것 — 앞에서 배운 max가 바로 이걸 하는 일이었죠.

Gt+1  =  maxa′ Q(s′, a′)
Q(s, a)  =  r  +  maxa′ Q(s′, a′) 지금 이 행동의 값  =  당장 받은 점수  +  도착한 칸에서 최선을 다했을 때의 값

세 줄로 이어 보면

Q(s, a) = GtQ의 정의 — 끝까지 받을 점수의 합
         = r + Gt+1총점을 지금과 나머지로 쪼갠다
         = r + max Q(s′, a′)나머지 = 도착한 칸의 최고 Q값

이것이 벨만 방정식(Bellman equation)입니다. Q를 계산하는 데 Q를 쓰고 있다는 점이 핵심이에요 — 자기 자신을 재료로 쓰는 식입니다.

왜 이게 지연 보상을 해결하나

목표 바로 앞 칸이 먼저 +1을 배웁니다. 그러면 그 앞 칸은 “옆 칸이 1점짜리네”를 보고 1을 얻고, 또 그 앞 칸도 1을 얻습니다.

점수가 목표에서부터 거꾸로, 한 칸씩 번져 나옵니다.

PART 3 · 계산 연습

한 걸음만 직접 계산해 봅시다

경우가 딱 세 가지뿐이에요.

🏁 s8 목표 +1  ·  🕳️ s4 구덩이 −1
그 외 이동은 전부 0점

경우 ①

아직 아무것도 모를 때

s0에서 ↓ → s3 도착. r = 0. s3의 네 값은 아직 0, 0, 0, 0

Q(s0, ↓) = 0 + max(0, 0, 0, 0) = 0

아무 일도 일어나지 않습니다. 초반에는 거의 전부 이 경우입니다.

경우 ②

종료 칸에 들어갈 때

s7에서 움직여 봅니다. 종료 칸에는 이어질 미래가 없으니 max Q = 0

s7에서 → → s8(🏁)  :  Q(s7, →) = 1 + 0 = 1
s7에서 ↑ → s4(🕳️)  :  Q(s7, ↑) = −1 + 0 = −1

여기서 처음으로 0이 아닌 값이 생깁니다. 받은 보상이 그대로 Q값이 됩니다.

경우 ③

옆 칸에 값이 생긴 다음

s6에서 → → s7 도착. r = 0. ②에서 계산한 덕분에 s7의 네 값이 이제 −1, 0, 0, 1

Q(s6, →) = 0 + max(−1, 0, 0, 1) = 1

점수를 하나도 못 받았는데 값이 1이 되었습니다. “1점짜리 칸으로 데려다줬으니까”요. (s7의 ↓와 ←가 아직 0인 건, 그쪽으로 가 본 적이 없어서입니다)

이 세 줄이 오늘의 전부입니다. ②로 씨앗이 심기고, ③이 반복되며 뒤로 번집니다.

빈 칸이 왜 위험한가

왼쪽 표에서 비어 있는 32칸은 “그쪽은 별로다”라는 뜻이 아닙니다. 가 본 적이 없다는 뜻입니다.

  • 더 좋은 길이 바로 옆에 있어도, 값이 0이라 고를 이유가 없습니다
  • 다른 곳에 더 큰 보상이 있었다면? 역시 영영 발견하지 못합니다
  • 지도가 바뀌거나 얼음이 미끄러우면, 빈 칸이 곧 사고입니다

“안 가 본 곳의 값이 0인 것은, 좋다는 뜻도 나쁘다는 뜻도 아닙니다. 모른다는 뜻입니다.”

EXPLOITATION vs EXPLORATION

단골집만 갈 것인가, 새 집을 뚫을 것인가

🍜 점심 고르기로 생각해 봅시다

  • 늘 가던 맛집만 간다 → 실패는 없지만, 더 좋은 집을 영영 모릅니다
  • 늘 새로운 집만 간다 → 가끔 대박, 하지만 망하는 날이 훨씬 많습니다

현실적인 답 — 평일엔 단골집(활용), 주말엔 모험(탐험). 그리고 새 동네로 이사한 첫 달엔 모험을 훨씬 많이 합니다.

용어 정리

활용

= Q값 1등 방향으로
탐험

2·3차시 밴딧에서 만난 그 딜레마입니다. 상태가 생겨도 딜레마는 그대로입니다.

ε-그리디 — 동전을 던져서 정한다

  • 확률 ε : 네 방향 중 아무거나 (탐험)
  • 확률 1−ε : argmax 방향 (활용)

ε-decay — ε을 1.0에서 시작해 0.05까지 줄여 갑니다.

이사 온 첫 달엔 여기저기 다녀 보고, 익숙해지면 단골집으로. 앞 슬라이드의 빈 칸이 생기지 않게 하는 방법입니다.

두 가지 방식

“가끔 딴 길로”를 만드는 두 가지 방법

방법 1

ε-그리디

if 난수 < ε:
    a = 아무 방향   # 완전 무작위
else:
    a = argmax Q(s, ·)

동전을 던져 탐험할지 말지를 먼저 정합니다. 탐험하기로 했다면 Q값을 아예 무시하고 아무 데나 갑니다.

방법 2

랜덤 노이즈 더하기

a = argmax( Q(s, ·) + 잡음 )
# 예) [0.81, 0.59, 0.66, −0.9]
#   + [0.05, 0.31, 0.12,  0.02]
#   = [0.86, 0.90, 0.78, −0.88] → ↓ 선택

Q값에 작은 무작위 수를 얹어서 순위를 살짝 흔듭니다. 잡음의 크기도 점점 줄여 갑니다.

무엇이 다른가

ε-그리디랜덤 노이즈
탐험할 때 고르는 것네 방향이 전부 똑같은 확률 2등·3등이 더 잘 뽑힘 — 순위를 흔들 뿐이라
성격가끔 완전히 엉뚱한 짓을 한다 괜찮아 보이는 것들 근처를 뒤진다
구덩이가 많을 때−1인 줄 알면서도 가끔 빠진다 −1은 잡음을 얹어도 낮아서 잘 안 간다

둘 다 널리 쓰입니다. 우리는 더 단순한 ε-그리디로 갑니다.

움직일 때와 배울 때가 다르다

움직일 때는 가끔 엉뚱한 방향으로 갑니다. 그런데 배울 때 쓰는 식은 max Q(s′, a′) — “거기서 최선을 다했다면”을 가정합니다.

즉, 엉뚱하게 걸으면서도 최선의 길을 배웁니다. 이 성질 때문에 Q러닝을 off-policy 알고리즘이라고 부릅니다.

γ · GAMMA

늦게 받는 1점은, 지금 받는 1점보다 못하다

표가 온통 1이 된 건 먼 점수와 가까운 점수를 똑같이 취급했기 때문입니다. 손잡이를 하나 더 답니다.

γ (감가율, discount factor) — 한 걸음 멀어질 때마다 점수에 곱해 주는 값 세 걸음 뒤의 +1점은 지금 기준으로 γ × γ × γ × 1 = γ³점의 가치
γ바로 앞 +11걸음 뒤2걸음 뒤3걸음 뒤이런 성격의 AI
01000눈앞의 점수만 본다 — 밴딧이 바로 이 경우
0.510.50.250.125성격이 급하다. 먼 보상은 거의 안 보임
0.910.90.810.729멀리 보되, 지름길을 선호 — 가장 많이 쓰는 값
11111100걸음을 돌아가도 똑같이 +1. 급할 게 없다

γ < 1이 하는 일 ①

멀리 있는 보상일수록 값이 작아지니, 짧은 길이 저절로 더 높은 값을 받습니다. “빨리 가라”고 따로 시키지 않아도 됩니다.

γ < 1이 하는 일 ②

끝이 없는 문제에서도 점수의 합이 무한대로 튀지 않게 눌러 줍니다.

ALGORITHM

Q러닝 전체 — 이게 다입니다

1989년 크리스 왓킨스(Chris Watkins)가 제안. 다음 시간에 이걸 그대로 코드로 옮깁니다.

Q ← 모든 칸이 0인 9 × 4 표

에피소드를 500번 반복:
    s ← 시작 칸 (s0)
    판이 끝날 때까지 반복:
        a ← ε-그리디로 방향 하나 고르기        # 활용 or 탐험
        s′, r, 끝났나 ← 환경.한칸이동(s, a)     # 실제로 움직인다

        목표 ← r                              # 끝났으면 여기까지
        if 안 끝났으면:
            목표 ← r + γ · max Q(s′, a′)        # 옆 칸 값을 끌어온다

        Q[s, a] ← 목표                         # 표에 적는다
        s ← s′

기억할 것은 세 줄

  • 고른다 — ε-그리디
  • 겪는다 — s′, r을 받는다
  • 적는다 — Q[s,a] ← r + γ·max Q(s′, a′)

두 개의 손잡이

γ얼마나 멀리 볼까
ε얼마나 헤맬까

다음 시간 실습의 마지막 과제가 이 셋을 돌려 보는 것입니다.

Q̂ · Q-hat

우리가 표에 적은 건 “진짜 Q”가 아닙니다

진짜 값 Q*(optimal Q)는 아무도 모릅니다. 우리가 가진 건 겪어 보고 추정한 값입니다.

Q̂  (학습 중인 우리 표)  →  Q*  (진짜 최적값 · optimal Q) 모자(hat)를 씌운 Q̂는 “추정치”라는 표시입니다

Q̂가 Q*에 반드시 도달한다고 증명된 조건

조건뜻우리 호수는?
① 결정론적 세계
deterministic world		 같은 칸에서 같은 방향 → 항상 같은 결과 ✓ 만족
② 상태·행동의 수가 유한 표를 끝까지 적을 수 있다 ✓ 36칸
③ 모든 칸을 충분히 자주 방문 안 가 본 칸은 영원히 모른다 ✓ ε-그리디

③번이 바로 탐험을 해야 하는 이론적인 이유입니다. “가끔 딴 길로”는 취향이 아니라 수렴의 조건이었던 겁니다.

①이 깨지면 — 미끄러운 얼음

같은 방향으로 가도 미끄러져 딴 데로 간다면, 한 번의 경험을 믿을 수 없습니다. → 같은 칸을 여러 번 겪어 평균을 내야 하고, 그러려면 식에 손잡이가 하나 더 필요합니다.

②가 깨지면 — 상태가 너무 많음

표를 끝까지 적는 것이 불가능해집니다. → 다음 슬라이드에서 이야기합니다.

“표를 다 적을 수 없다면, 표 대신 계산해 주는 무언가를 두면 되지 않을까?”

그 “무언가”로 신경망을 쓰는 방법이 있습니다. 이름은 딥 Q 네트워크(DQN) — 2015년에 아타리 게임 49종을 사람 수준으로 플레이해 화제가 된 그 방법입니다.

놀랍게도 벨만 방정식도, ε-그리디도, 오늘 배운 것 그대로입니다. 표를 신경망으로 바꾼 것뿐이죠. 다만 그 앞은 딥러닝의 영역이라, 오늘은 이런 길이 있다는 것만 알고 넘어갑니다.

오늘 손에 넣은 것

  • Q(s,a) — 이 칸에서 이 방향으로 갔을 때 끝까지 받을 점수
  • 정책 — π(s) = argmaxa Q(s,a)
  • 벨만 방정식 — 처음엔 Q = r + max Q(s′,a′)
  • ε을 달았다 — 안 가 본 칸을 알아내기 위해
  • γ를 달았다 — 전부 1인 표에서 가까운 길을 고르기 위해
  • 그래서 완성된 식 — Q(s,a) ← r + γ·max Q(s′,a′)
