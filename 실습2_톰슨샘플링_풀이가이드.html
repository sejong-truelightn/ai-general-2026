이 실습이 묻는 것

기계 5대가 있고, 각 기계가 당첨될 확률은 서로 다릅니다. 그런데 그 확률을 우리는 모릅니다. 1,000번 안에 점수를 최대로 모으려면, 당겨보면서 알아내는 수밖에 없습니다.

탐험(explore) — 잘 모르는 기계를 당겨서 정보를 얻는다. 지금은 손해일 수 있다.
활용(exploit) — 지금까지 제일 좋아 보이는 기계를 당겨서 점수를 번다. 사실은 틀렸을 수도 있다.
이 둘을 어떤 비율로 섞을 것인가 — 세 전략(그리디 / ε-그리디 / 톰슨 샘플링)은 이 질문에 대한 서로 다른 대답입니다.

모든 전략의 코드는 사실 똑같은 뼈대입니다. “몇 번 기계를 당길지 정한다 → 당긴다 → 결과를 기록한다”의 반복이고, 빈칸은 전부 첫 단계, 기계를 고르는 부분에만 있습니다. 즉 여러분이 채우는 건 선택 규칙 하나뿐입니다.

환경 만들기 — 이 코드가 정한 세 가지

노트북 1번 셀은 짧지만 실습 전체의 규칙을 정합니다. 그림 세 장으로 나눠 보겠습니다.

① 정보의 벽 — TRUE_P는 코드에 있지만, AI는 읽지 않는다

② pull(i) — 0과 1 사이에 선을 하나 긋는 일

③ 점수는 0점부터 1000점까지가 아니다

④ argmax_random — 값이 아니라 번호를, 동점이면 공평하게

이 함수는 이미 완성되어 있으니 고칠 필요는 없습니다. 하지만 무슨 일을 하는지는 알아야 빈칸 ②를 채울 수 있습니다. 우리에게 필요한 건 “가장 높은 승률이 얼마인가”가 아니라 “그게 몇 번 기계인가”이기 때문입니다.

v 자리에는 리스트가 들어갑니다. 숫자 하나가 아닙니다. 기계 5대의 숫자가 기계 번호 순서대로 담긴 길이 5짜리 리스트 — 빈칸 ②에서 여러분이 만드는 q가 바로 그것입니다.
그래서 함수 안에서 len(v)는 기계 개수 5, v[i]는 i번 기계의 숫자가 됩니다.
def argmax_random(v):        # v = 기계별 숫자 5개가 든 리스트
    m = max(v)                       # 1) 최댓값이 얼마인지
    cands = []                       # 2) 그 값을 가진 번호를 모은다
    for i in range(len(v)):
        if v[i] == m:
            cands.append(i)
    return random.choice(cands)      # 3) 그중 하나를 무작위로

실제로 부를 때는 이렇게 생겼습니다. 리스트를 넣으면 번호가 나옵니다.

q = [0.33, 0.00, 0.80, 0.25, 0.71]   # 기계 A, B, C, D, E 순서
argmax_random(q)                     # → 2   (가장 큰 0.80이 있는 자리 = 기계 C)

왜 q.index(max(q)) 로는 안 되나

index()는 항상 앞쪽 번호를 돌려줍니다. 위 상황에서 A·C·E가 똑같이 1.00인데도 매번 A가 뽑히고, 그리디는 A에 갇힌 채 1,000번을 끝냅니다. C가 진짜 정답이었어도 말이죠.

더 나쁜 건, 이게 실험을 망친다는 점입니다. 400번을 반복해도 결과가 늘 “앞번호 기계 쪽”으로 기울어서, 히스토그램이 전략의 성질이 아니라 기계를 나열한 순서를 보여주게 됩니다. 전략끼리 공정하게 비교하려면 동점은 동전으로 갈라야 합니다.
쓰는 것돌려주는 값q = [1.0, 0.0, 1.0, 0.0, 1.0] 이면
max(q)가장 큰 값1.0 — 기계 번호가 아님
q.index(max(q))가장 큰 값의 첫 번호항상 0 (A만 계속)
argmax_random(q)동점 중 무작위 번호0 또는 2 또는 4
np.argmax(q)가장 큰 값의 첫 번호항상 0 — 넘파이판 index(max())

정리하면 — argmax_random은 “1등의 점수”가 아니라 “1등의 자리”를 알려주는 도구이고, 1등이 여럿일 때 순서 때문에 생기는 보이지 않는 편애를 막아 줍니다.

빈칸 ②

그리디 — 지금 1등을 고르기

빈칸을 채우기 전에 — 함수 전체를 읽어 봅시다

세 전략은 모두 같은 뼈대입니다. 이 뼈대를 한 번만 이해하면 ε-그리디와 톰슨 샘플링은 읽기만 해도 됩니다.

ⓐ 준비 — 반복문 밖에서 딱 한 번

wins   = [0] * K      # [0, 0, 0, 0, 0] · 기계별 당첨 횟수
trials = [0] * K      # [0, 0, 0, 0, 0] · 기계별 시도 횟수
total  = 0           # 지금까지 모은 총점
history = []          # 매 판의 누적 점수를 쌓아 둘 곳
  • [0] * K 는 [0, 0, 0, 0, 0] 를 만드는 관용구입니다. [0,0,0,0,0] 라고 직접 쓰지 않는 이유는, 나중에 기계를 7대로 늘려도 이 줄을 고칠 필요가 없기 때문입니다.
  • wins와 trials는 기계 번호가 곧 자리 번호입니다. trials[2]는 “C를 몇 번 당겼나”. 빈칸 ②에서 승률을 계산할 때 이 두 리스트를 짝지어 씁니다.
  • history는 전략의 판단에 쓰이지 않습니다. 나중에 “누적 점수 그래프”(7번 셀 오른쪽)를 그리기 위한 기록일 뿐입니다.
  • 이 네 줄이 for 문 바깥에 있는 게 중요합니다. 안으로 들어가면 매 판 0으로 초기화돼서 아무것도 학습하지 못합니다.

ⓑ 첫 5번 — 몸풀기 분기

if 0 in trials:                  # 아직 한 번도 안 당긴 기계가 남아 있나?
    i = trials.index(0)         # 그중 가장 앞 기계를 고른다
  • 0 in trials → “trials 안에 0이 하나라도 있니?” 참/거짓을 돌려줍니다.
  • trials.index(0) → “0이 처음 나오는 자리 번호”. 그래서 t = 0,1,2,3,4 동안 A→B→C→D→E를 한 번씩 당기게 됩니다.
  • 왜 이게 꼭 필요한가 — 이 분기가 없으면 아래에서 wins[j] / trials[j]를 계산할 때 0 / 0 이 되어 ZeroDivisionError로 멈춥니다. 즉 “나눗셈이 가능해지도록 만드는 준비 단계”입니다.
  • 동시에, 이 다섯 판이 그리디의 운명을 정합니다. 여기서 C가 우연히 꽝이 나면 C는 다시 뽑히지 않습니다.

ⓒ 당기고 기록하기 — 이 다섯 줄은 세 전략 공통

r = pull(i)           # 1(당첨) 또는 0(꽝)
trials[i] += 1        # i번 기계를 한 번 더 당겼다
wins[i]   += r        # 당첨이면 +1, 꽝이면 +0
total     += r        # 총점에도 더한다
history.append(total) # 지금까지의 누적 점수를 기록
  • wins[i] += r 가 이 코드에서 가장 영리한 한 줄입니다. r이 1 아니면 0이라서 if 없이 “당첨이면 늘리고 꽝이면 그대로”가 됩니다. (톰슨 셀에서는 wins와 loses를 따로 세야 해서 if를 씁니다.)
  • trials[i] += 1 은 결과와 상관없이 항상 1 늘어납니다. 당첨이든 꽝이든 “당긴 건 당긴 것”이니까요.
  • history.append(total) 는 그때그때의 총점을 사진처럼 찍어 두는 것입니다. 1,000줄이 쌓이면 그게 곧 누적 점수 곡선의 y값이 됩니다.
  • 이 다섯 줄은 반드시 i가 정해진 다음에 와야 합니다. 그래서 if/else 블록 바깥, 같은 들여쓰기에 있습니다.

ⓓ 돌려주는 값 세 개

return total, trials, history

그래서 부를 때는 score, trials, _ = greedy() 처럼 셋으로 받습니다. _ 는 “이번엔 안 쓸 값” 이라는 뜻의 관례적인 이름입니다 — history는 여기서 필요 없으니까요.

추정 확률을 구하고, 1등 기계를 고른다

def greedy()
# ✏️ 실습 ② : 기계별 추정 확률(승률)을 계산해 q에 담고,
#            그중 가장 큰 값을 가진 기계 번호를 i에 담으세요.
q = 여기를_채우세요
i = 여기를_채우세요

무엇을 만들어야 하나?

q 는 길이 5짜리 리스트여야 합니다. q[0]은 A의 추정 승률, q[1]은 B의 추정 승률 … 그리고 i 는 그중 가장 큰 값이 있는 자리 번호입니다.

생각 순서

  1. 기계 하나의 추정 확률은? → wins[j] / trials[j] (당첨 ÷ 시도)
  2. 그걸 5대 전부에 대해 만들려면? → 빈 리스트를 하나 만들고 for j in range(K) 로 돌면서 append
  3. 가장 큰 값의 위치가 필요하다 → 위 셀에 이미 만들어 둔 argmax_random(v)
힌트 한 줄만 더

뼈대는 이렇습니다. 가운데 한 줄만 채우면 됩니다.

q = []
for j in range(K):
    q.append( ??? )

그리고 argmax_random 은 리스트를 넣으면 번호를 돌려줍니다.

정답 보기
q = []                              # 빈 리스트에서 시작
for j in range(K):              # 기계 0번부터 4번까지
    q.append(wins[j] / trials[j])   # 그 기계의 승률을 뒤에 붙인다

i = argmax_random(q)                # 1등의 번호
빈칸 한 줄을 여러 줄로 늘려도 됩니다. q = 여기를_채우세요 줄을 지우고 위 네 줄을 같은 들여쓰기 위치에 붙여 넣으면 됩니다.

argmax_random 을 쓰는 이유: 초반에는 승률이 1.0으로 같은 기계가 여럿 생깁니다. 그냥 index(max(q))를 쓰면 늘 앞번호 기계만 뽑혀서 결과가 한쪽으로 치우칩니다. 동점이면 무작위로 고르는 게 공정합니다.

자주 하는 실수 — q = wins / trials (리스트끼리는 나눗셈이 안 됩니다) · i = max(q) (이건 값이지 번호가 아닙니다. 기계 번호 0.83번은 없습니다)
한 걸음 더 — 매번 다시 계산하지 않고 q를 갱신해 나가기

“어차피 필요한 건 승률뿐인데, 매 판 5번씩 다시 나누지 말고 q 자체를 들고 다니며 고치면 되지 않나?” — 맞습니다. 그리고 그 방식이 강화학습 교과서가 쓰는 형태입니다.

q = [0.0] * K              # 추정 승률을 직접 들고 다닌다
n = [0] * K                # 기계별 시도 횟수
...
    r = pull(i)
    n[i] += 1
    q[i] += (r - q[i]) / n[i]   # 증분 평균 — 이 한 줄이 전부

왜 이게 평균이 되나 — r - q[i]는 “이번 결과가 지금 추정보다 얼마나 높/낮았나”, 즉 오차입니다. 그 오차를 1/n 만큼만 따라갑니다. 열 번째 판이면 10분의 1, 백 번째 판이면 100분의 1 — 그래서 판이 쌓일수록 추정이 잘 안 흔들리게 되고, 결과는 당첨 / 시도와 정확히 같은 값이 됩니다.

이득 — 매 판 K번 하던 계산이 1번으로 줄고, wins 리스트가 필요 없어집니다. 기계가 5대일 땐 차이가 없지만 후보가 1만 개인 광고 추천이라면 이야기가 달라집니다.

이 모양을 기억해 두세요.
추정 ← 추정 + 학습률 × (받은 값 − 추정)
앞으로 배울 Q-러닝의 갱신식과 글자 그대로 같은 꼴입니다. 여기서는 학습률 자리에 1/n이 들어가 있을 뿐이고, 그 자리에 0.1 같은 고정값을 넣으면 “오래된 결과를 잊고 최근을 더 믿는” 버전이 됩니다 — 도전 과제 5번(중간에 확률이 바뀌면?)의 출발점이 바로 이것입니다.

그런데 이 실습은 왜 매번 다시 계산할까요? 기계가 5대·1,000판이라 속도 차이가 전혀 없고, q = 당첨 / 시도 라고 적어야 승률의 정의를 코드에서 그대로 읽을 수 있기 때문입니다. 증분식은 “왜 이게 평균이지?”를 한 번 더 설명해야 하니까요.

직접 확인해 본 결과

  • 같은 seed로 두 방식을 돌리면 q 값이 소수점 16자리까지 일치합니다(오차 2.2e-16).
  • 다만 200판 중 21판은 총점이 갈립니다. 그 미세한 오차 때문에 동점 판정이 어긋나 argmax_random이 다른 기계를 고르고, 거기서부터 판이 달라지기 때문입니다. 평균은 물론 같습니다.
왜 그리디가 위험한가 — 진짜 좋은 기계 C가 첫 시도에서 우연히 꽝(승률 0.00)이 나면, C는 영원히 다시 뽑히지 않습니다. 히스토그램의 봉우리가 여러 개로 갈라지는 이유가 이것입니다. 봉우리 위치 150 / 250 / 400 / 550 / 650 은 각각 “B에 갇힘 / D에 갇힘 / A에 갇힘 / E에 갇힘 / C에 갇힘”을 뜻합니다.

한 판이 아니라 400판 — repeat() 가 하는 일

def repeat(strategy, runs=1000, eps=None):
    scores = []
    for run in range(runs):
        random.seed(run)                  # 이 판의 '운'을 고정
        np.random.seed(run)

        if eps is None:                 # greedy, thompson
            total = strategy()[0]
        else:                            # eps_greedy
            total = strategy(eps=eps)[0]

        scores.append(total)              # 총점만 모은다
    return np.array(scores)
  • repeat(greedy) — 괄호 없이 함수 이름만 넘깁니다. repeat(greedy()) 라고 쓰면 먼저 한 판을 실행한 결과(숫자)가 넘어가 버려서 오류가 납니다. 함수도 값처럼 넘길 수 있다는 게 여기 핵심입니다.
  • random.seed(run) — 씨앗이 같으면 난수도 같은 순서로 나옵니다. run을 0, 1, 2 …로 바꾸며 매번 다른 운을 만들되, 세 전략이 모두 똑같은 운의 목록을 겪게 만듭니다. 그래야 “전략이 좋아서 이긴 것”과 “운이 좋아서 이긴 것”을 가를 수 있습니다.
  • eps=None — None은 “값이 없다”는 뜻의 특별한 값입니다. repeat(greedy) 처럼 eps를 안 적으면 None이 되어 strategy() 를 그냥 부르고, repeat(eps_greedy, eps=0.3) 처럼 적어 주면 strategy(eps=0.3) 으로 부릅니다. 그리디와 톰슨은 eps라는 매개변수가 아예 없기 때문에 이렇게 갈라 줘야 합니다.
  • strategy()[0] — 앞에서 return total, trials, history 였으니 [0]은 총점입니다.
  • np.array(...) 로 바꾸는 이유는 단 하나 — 그래야 .mean(), .std(), .min()을 바로 쓸 수 있습니다.

seed는 무엇을 고정하는가 — “난수 대기열”

random.seed(run) 과 strategy() 는 직접 연결되어 있지 않습니다. 두 줄 사이에 화살표가 없는데도 영향을 주고받는 이유는, 둘 다 파이썬이 하나만 들고 있는 난수 생성기를 함께 쓰기 때문입니다. seed는 그 생성기의 상태를 특정 값으로 되감는 명령이고, 그 뒤에 나올 숫자의 순서 전체가 그 순간 확정됩니다.

  • 무작위가 들어오는 통로는 pull() 하나뿐입니다. return 1 if random.random() < TRUE_P[i] else 0 — 당첨이냐 꽝이냐는 오직 여기서 꺼낸 숫자 하나로 정해집니다. seed를 고정한다는 건 결국 “몇 번째 당김이 당첨일지”를 미리 정해 두는 것입니다.
  • np.random.seed(run) 이 따로 있는 이유 — 넘파이는 자기만의 난수 생성기를 씁니다. 톰슨 샘플링의 np.random.beta(...) 는 파이썬 쪽 seed의 영향을 받지 않기 때문에, 두 생성기를 모두 고정해야 톰슨도 재현됩니다.
  • argmax_random 안의 random.choice 도 이 대기열에서 숫자를 하나 꺼내 씁니다. 전략이 난수를 몇 개나 쓰느냐에 따라 이후 pull()이 받아 가는 숫자가 밀리는 이유가 이것입니다.
왜 굳이 씨앗을 고정할까요 — 공정한 시합을 위해서입니다. repeat(greedy, runs=300) 은 seed(0)부터 seed(299)까지 300가지 운으로 겨룹니다. 나중에 repeat(thompson, runs=300) 을 돌릴 때도 똑같이 seed(0)부터 시작합니다. 씨앗을 고정하지 않으면 “전략이 좋아서 이겼는지, 그날 운이 좋았는지”를 구분할 수 없습니다.
다만 “완전히 똑같은 판”은 아닙니다. 같은 대기열에서 출발하지만, 전략마다 어느 기계를 몇 번째로 당기는지가 다르고 난수를 꺼내 쓰는 개수도 달라서, 중간부터는 서로 다른 숫자를 받게 됩니다. 보장되는 것은 “같은 출발선”이지 “같은 결과”가 아닙니다. 그래서 한 판이 아니라 300판의 평균으로 비교하는 것이고, 그렇게 하면 남은 운의 차이는 씻겨 나갑니다.

randrange와 randint — 끝 값을 포함하느냐

둘 다 “정수 하나를 무작위로” 뽑지만 범위를 읽는 규칙이 다릅니다. 이름이 비슷해서 바꿔 쓰기 쉽고, 바꿔 쓰면 몇 백 번 잘 돌다가 갑자기 죽습니다.

쓰는 것나오는 값K = 5 일 때
random.randrange(K)0 이상 K 미만0 1 2 3 4 ✔
random.randint(0, K-1)0 이상 K-1 이하0 1 2 3 4 ✔
random.randint(0, K)0 이상 K 이하0 1 2 3 4 5 ✘
random.choice(range(K))0 이상 K 미만0 1 2 3 4 ✔
왜 하필 randrange를 권할까요 — 이 숫자는 곧바로 pull(i) 의 리스트 자리 번호로 쓰입니다. 리스트의 자리는 항상 0부터 길이-1까지이고, 그건 for j in range(K) 가 도는 범위와 정확히 같습니다. randrange(K)는 그 범위를 글자 그대로 적은 것이라 K-1 같은 계산을 손으로 할 일이 없습니다.
틀렸을 때 나타나는 증상 — randint(0, K) 로 쓰면 탐험할 때 6번에 1번꼴로 5가 나옵니다. 그러면 TRUE_P[5] 를 찾다가 IndexError: list index out of range 로 멈춥니다. 바로 안 죽고 한참 잘 돌다가 죽는 게 함정입니다 — ε=0.1이면 탐험 자체가 10번에 1번뿐이니까요.
실행 결과에서 확인할 것 — ε을 키우면 “최악의 점수”는 올라가지만(안 망함) “평균”은 어느 지점부터 다시 내려갑니다. 가장 좋은 ε은 이 문제의 답을 다 알고 나서야 알 수 있습니다. 실전에서는 미리 정할 수 없다는 뜻이고, 이것이 ε-그리디의 근본적 약점입니다.
준비

베타 분포 — “얼마나 확신하는가”를 그림으로

그리디는 기계 하나를 숫자 하나로 기억했습니다. 그래서 1승 1패(0.5)와 50승 50패(0.5)를 구별하지 못합니다. 베타 분포는 이 차이를 곡선의 폭으로 적어 둡니다.

Beta(당첨+1, 꽝+1) — 곡선이 높은 곳 = 진짜 확률이 그쯤일 것 같다. 곡선이 넓다 = 아직 잘 모르겠다. 안 당겨본 기계는 완전히 평평합니다(“0부터 1까지 뭐든 가능”).
+1을 붙이는 이유는 0번 당겨본 기계도 계산이 되도록 하기 위해서입니다.

ⓐ 왜 trials가 아니라 loses인가

wins  = [0] * K       # 당첨 횟수
loses = [0] * K       # 꽝 횟수  ← 새로 생긴 것

그리디가 계산하던 승률은 당첨 / 시도라서 시도 횟수만 있으면 됐습니다. 하지만 톰슨이 만드는 것은 Beta(당첨 + 1, 꽝 + 1) — 당첨과 꽝을 각각 따로 넣어야 합니다. 그래서 “몇 번 당겼나” 대신 “몇 번 이기고 몇 번 졌나”를 세는 것으로 바뀌었습니다.

사실 loses는 trials - wins 로도 구할 수 있습니다. 그런데도 따로 세는 이유는, 코드가 베타 분포의 모양 Beta(당첨+1, 꽝+1) 과 눈으로 봐도 똑같이 생기게 하기 위해서입니다. 빈칸 ④를 채울 때 이 대응이 그대로 보입니다.

ⓑ 한 줄이 네 줄로 늘어난 이유

r = pull(i)
if r == 1:
    wins[i]  += 1
else:
    loses[i] += 1
total += r

그리디에서는 wins[i] += r 한 줄이면 충분했습니다. r이 0일 때 아무 일도 안 일어나도 괜찮았으니까요. 하지만 여기서는 꽝일 때도 할 일이 있습니다 — loses를 늘려야 하죠. 그래서 갈래가 필요합니다.

total += r 만은 갈래 밖에 있습니다. 총점은 당첨일 때만 오르니 if 없이도 맞습니다.

ⓒ 몸풀기 분기가 사라졌습니다 — 여기가 핵심입니다

그리디에는 반드시 있어야 했던 if 0 in trials: 가 톰슨에는 아예 없습니다. 한 번도 안 당겨본 기계라도 Beta(0 + 1, 0 + 1) = Beta(1, 1) — 0부터 1까지 완전히 평평한 분포가 되어 계산이 그냥 됩니다.

“나눗셈이 안 되니 일단 한 번씩 당겨보자”는 땜질이 필요 없어졌습니다. 안 당겨본 기계는 곡선이 평평해서 큰 숫자가 뽑힐 가능성이 넉넉히 열려 있고, 그래서 저절로 선택됩니다. 그리디가 if문으로 억지로 시키던 일을, 톰슨은 분포의 모양이 대신 해 줍니다.

ⓓ 마지막 한 줄 — trials는 왜 여기서 만드나

trials = []
for j in range(K):
    trials.append(wins[j] + loses[j])
return total, trials, history

전략이 판단할 때는 trials를 쓰지 않습니다. 오직 화면에 “몇 번 당겼나”를 찍어 보여주기 위해 마지막에 한 번 계산합니다. 또 하나의 이유는 돌려주는 값의 모양을 그리디와 똑같이 맞추기 위해서입니다 — 그래야 repeat(thompson) 이나 avg_history() 가 고치지 않고 그대로 돌아갑니다.

“total처럼 반복문 안에서 세면 안 되나요?” — 됩니다
r = pull(i)

else:

난수를 더 쓰지도 않으니 점수까지 한 자리도 달라지지 않습니다. 그리디와 나란히 놓고 비교하기에는 오히려 이 쪽이 편할 수도 있습니다. 그런데도 노트북이 마지막에 계산하는 데는 두 가지 이유가 있습니다.

1. 같은 사실을 두 곳에서 관리하게 됩니다

trials는 언제나 wins + loses 입니다 — 새로운 정보가 하나도 없습니다. 반복문 안에서 따로 세면, 나중에 if/else 한쪽만 고치거나 도전 과제로 코드를 손대다가 trials[i] += 1을 빠뜨렸을 때 세 숫자가 서로 안 맞는데 에러는 안 나는 상태가 됩니다. 마지막에 한 번 계산하면 어긋날 방법이 없습니다.

2. “이건 판단에 안 쓴다”는 표시가 됩니다

그리디에서 trials는 승률 계산에 반드시 필요한 재료였습니다. 반면 톰슨은 wins와 loses만 보고 결정합니다. trials를 반복문 밖으로 빼 두면 “이건 화면에 찍기 위한 것”이라는 사실이 코드의 위치만으로 드러납니다.

정답이 하나인 문제가 아닙니다. 동작은 같고, 무엇을 강조하고 싶은가의 차이입니다. 지금 구조는 “톰슨이 실제로 보는 것은 당첨과 꽝, 둘뿐”을 강조하는 쪽입니다.

넘파이에도 같은 일을 하는 np.argmax가 있습니다(int(...)는 넘파이 정수를 파이썬 정수로 바꾸는 것). 앞으로 AI 코드에서 자주 만나게 되니 이름만 기억해 두세요. 다만 samples는 실수라 동점이 사실상 없어서 어느 쪽을 써도 결과는 같습니다.

단, 점수가 소수점까지 똑같이 나오지는 않습니다. argmax_random은 안에서 random.choice를 부르느라 난수를 하나 더 쓰기 때문에, 같은 seed라도 이후 pull()의 결과가 어긋납니다. 평균은 통계적으로 같습니다 — 이것도 “씨앗이 같으면 결과가 같다”가 무슨 뜻인지 보여주는 좋은 예입니다.

자주 하는 실수 — i = max(samples) 는 값(0.72)을 줍니다. 우리에게 필요한 건 번호(1)입니다. “가장 큰 값”과 “가장 큰 값의 자리”는 다르다 — 이 구분이 실습 전체의 핵심 문법입니다.
왜 이게 탐험과 활용을 저절로 섞는가
많이 당겨본 좋은 기계 → 곡선이 좁고 오른쪽 → 늘 높은 숫자가 뽑힘 → 자주 선택됨 (활용)
거의 안 당겨본 기계 → 곡선이 넓음 → 가끔 운 좋게 큰 숫자가 뽑힘 → 다시 기회를 얻음 (탐험)
ε처럼 “탐험 비율”을 사람이 정해주지 않았는데도, 확신이 없을수록 더 탐험하게 됩니다.

곡선이 갈라지는 순간

노트북 6번 셀과 같은 그림입니다. 버튼을 눌러 당길수록 곡선이 좁아지고, 좋은 기계가 오른쪽으로 떨어져 나갑니다.

노트북 6번 셀에서 눈여겨볼 한 글자 — [:]

if t in snaps:
    shots[t] = (wins[:], loses[:])   # 지금 상태의 사본을 저장

wins[:] 는 리스트의 복사본을 만듭니다. 그냥 wins라고 적으면 같은 리스트를 가리키는 이름만 저장되어서, 뒤에서 wins가 계속 바뀌는 동안 10번째·50번째 스냅샷이 전부 마지막 상태로 변해 버립니다. 다섯 칸이 전부 똑같은 그림이 나온다면 십중팔구 이 [:]를 빠뜨린 것입니다.

나머지는 thompson()과 같은 코드에 “정해진 판에서 사진만 한 장 찍는” 줄이 끼어든 것뿐입니다 (snaps = (0, 10, 50, 200, 1000)).

도전 과제 방향 힌트

  • N을 200으로 — 톰슨은 초반에 여러 기계를 찔러보는 데 투자합니다. 회수할 시간이 없으면 이점이 사라집니다.
  • 확률을 비슷하게 (0.51~0.47) — 구별할 정보가 적으니 어떤 전략도 오래 헤맵니다. 대신 틀려도 손해가 작다는 점도 같이 보세요.
  • ε 감소 eps = 1.0 / (t + 1) — 대개 고정 ε보다 낫습니다. 톰슨은 곡선이 좁아지면서 같은 일을 자동으로 합니다.
  • 중간에 확률 뒤섞기 — 톰슨도 결국 따라잡지만, 이미 좁아진 곡선을 되돌리는 데 시간이 걸립니다. 최근 결과에 가중치를 주는 게 해법의 출발점입니다.
